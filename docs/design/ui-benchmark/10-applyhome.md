## 청약홈 — 홈 (https://www.applyhome.co.kr/co/coa/selectMainView.do, 관찰일 2026-10-14, evidence_id applyhome-home-rea-desktop · applyhome-home-desktop · applyhome-home-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개(크기·위치 순):
  1. "오늘의 청약" 아래 큰 숫자 카드 두 장: 지금 접수 중인 공고 **N건**(채운 강조색 카드), 오늘 당첨자 발표 **N건**(테두리 카드). 숫자가 화면에서 가장 크다.
  2. 청약 캘린더 바로가기(가로 전체 폭 카드)
  3. "내 청약 준비" 펼침 카드(가점 계산·자격 진단으로 가는 입구, 기본은 접힘)
- 정보 계층: 1단 = "오늘 넣을 수 있는 게 몇 개인가 / 오늘 발표가 몇 개인가"(행동 단위 숫자 2개) → 2단 = 캘린더·내 준비 → 3단 = 주택 유형별 목록 입구(APT / 잔여세대 / 오피스텔 등), 공지사항, 하단 링크(용어·제도 안내·규제지역)
- 묶음 단위: 큰 카드(행동 진입점). 표 없음. 공지는 날짜 붙은 리스트.
- 숫자 표기: 정수 + "건". 기준 시점은 "오늘"이라는 제목으로만 표시(날짜·시각 없음). 접수 가능 시간대(평일 낮 시간)를 카드 안 작은 글씨로 함께 둔다.
- 상태·라벨 표현: 상태를 배지로 쓰지 않고 카드 제목 자체가 상태("진행 중", "발표")다.
- 필터·정렬: 없음.
- 용어 처리: 홈에서는 쉬운 동사형 문장("확인하기", "준비해 볼까요")으로 감싼다. 용어설명·제도 안내는 푸터 링크로만 노출.
- 모바일에서 달라지는 것: 숫자 카드 2장이 2열을 유지하고 더 커진다. 카드 제목이 더 쉬운 말로 바뀐다("진행 중인 공고" → "접수 가능한 공고" 식). 상단 문의 전화 띠는 그대로 남는다.
- 우리에게 쓸 만한 패턴:
  - 대시보드 첫 줄을 "지금 접수 중 N곳 / 이번 주 발표 N곳"처럼 **사용자 행동 단위의 개수 카드**로 시작한다(G1). 숫자는 API가 준 일정에서 센 값만.
  - 접수 가능 시간처럼 "실제로 넣을 때 막히는 조건"을 숫자 카드 바로 아래 작은 글씨로 붙인다.
  - 자격·가점처럼 사람마다 다른 정보는 기본 접힘 카드로 따로 둔다.
- 우리에게 맞지 않는 것과 이유: 상단 문의 전화 띠, 기관 홍보 배너 줄(공공기관 고지용), 일러스트 아이콘(시각적 무게만 늘린다).

## 청약홈 — 목록: APT 분양정보/경쟁률 (https://www.applyhome.co.kr/ai/aia/selectAPTLttotPblancListView.do, 관찰일 2026-10-14, evidence_id applyhome-list-rea-desktop · applyhome-list-desktop · applyhome-list-full · applyhome-list-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. 큰 페이지 제목과 경로(브레드크럼)
  2. 안내 상자(무엇을 볼 수 있는 화면인지 한 문장)
  3. 검색 폼(기간 시작·끝 월, 주택구분, 공급지역, 단지명, 분양/임대 체크박스) — **결과 표는 첫 화면 밖**. 모바일은 첫 화면 전체가 폼이다.
- 정보 계층: 1단 = 없음(요약·건수 강조 없음, "총게시물 N"이 표 위 오른쪽 작은 글씨) → 2단 = 11열 표(지역·주택구분·분양/임대·단지명·시공사·문의처·모집공고일·청약기간·당첨자발표·특별공급 신청현황·1·2순위 경쟁률) → 3단 = 단지명 클릭 시 공고 요약 팝업, 경쟁률·신청현황 버튼 팝업
- 묶음 단위: 표 하나. 경쟁률·신청현황은 셀 안 버튼 → 팝업으로 펼친다(목록 표에는 숫자를 넣지 않음).
- 숫자 표기: 날짜는 YYYY-MM-DD, 청약기간은 "시작 ~ 끝" 범위. 오늘 기준 D-day 없음.
- 상태·라벨 표현: **접수중/마감/예정 배지가 없다.** 사용자가 청약기간과 오늘 날짜를 직접 비교해야 한다. 표 위 주의 문구 3줄(단지명 누르면 공고, 열 제목 누르면 정렬, 실제 공고문이 우선)로 "이 표는 참고용, 원문이 이긴다"를 밝힌다. 경쟁률을 아직 낼 수 없는 단지는 버튼 대신 "사업주체 문의" 텍스트.
- 필터·정렬: 기본 기간 = 최근 12개월(최대 12개월만 조회). 정렬은 단지명·청약기간·당첨자발표 3개 열 제목 클릭. 한 페이지 10행 + 페이지 번호. 알림 신청 버튼이 필터 옆에 있다.
- 용어 처리: 없음. "민영/국민", "분양전환 가능임대" 같은 구분어를 설명 없이 그대로 쓴다.
- 모바일에서 달라지는 것: 폼이 2열로 접히고 첫 화면을 다 차지한다. 표는 그대로(가로 스크롤).
- 우리에게 쓸 만한 패턴:
  - "이 화면 값은 요약이고 원문(공고문)이 우선"이라는 한 줄 고지를 목록 표 위에 고정한다(우리 출처 원칙과 같은 방향).
  - 경쟁률처럼 단지별로 행이 많은 세부 값은 목록에 넣지 않고 "열기" 버튼으로 미룬다(G2 표 열 수 줄이기).
  - 값이 아직 없을 때 빈칸이 아니라 "왜 없는지/어디에 물어야 하는지" 텍스트를 넣는다(우리 "확인 불가(사유)"와 같다).
- 우리에게 맞지 않는 것과 이유: 결과보다 폼이 먼저 오는 배치(초보자는 첫 화면에서 아무 단지도 못 본다), 상태 배지 없이 날짜만 주는 방식(우리 D± 규칙보다 약하다), 11열 고정 표.

## 청약홈 — 상세: 입주자모집공고 주요정보 팝업 (https://www.applyhome.co.kr/ai/aia/selectAPTLttotPblancDetail.do?houseManageNo=…&pblancNo=…, 관찰일 2026-10-14, evidence_id applyhome-detail-rea-desktop · applyhome-detail-full · applyhome-detail-mobile · applyhome-detail-rea-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. 단지명이 머리글인 2열 정보표(공급위치·공급규모 N세대·문의처)
  2. 문의 전화 버튼(강조색)
  3. "모집공고문 보기" 버튼(원문 PDF로 가는 단일 입구) → 바로 아래 청약일정 표
- 정보 계층(위→아래 고정 순서): 1단 = 어디·몇 세대·누구에게 묻나 → 2단 = **청약일정 표**(모집공고일 / 특별공급·1순위·2순위 각각의 해당지역·기타지역 날짜·접수 장소 / 당첨자 발표일 / 계약일) → 3단 = 공급대상(주택형·공급면적·일반/특별/계 세대수) → 특별공급 유형별 세대수(10열) → **공급금액(최고가 기준)·2순위 청약금·입주예정월** → 시행·시공사
- 묶음 단위: 섹션 제목 + 표 + 표 아래 별표(*) 각주. 탭·아코디언 없음. 한 페이지 세로 나열.
- 숫자 표기: 금액은 "단위: 만원"을 표 오른쪽 위에 한 번만 적고 셀에는 천 단위 쉼표 정수(예: 9만 단위 다섯 자리). 면적은 소수 4자리 그대로. 세대수 합계 행("계")을 표 끝에 둔다. 입주예정월은 YYYY.MM.
- 필요한 돈 표시: **분양가는 주택형별 "최고가 기준" 한 값만**. 계약금·중도금·잔금 비율과 납부 일정은 이 화면에 없고 "층·동·호별 세부 금액은 공고문 참고" 각주로 원문에 넘긴다. 2순위 청약금은 "통장으로 청약(청약금 없음)"처럼 문장으로 적는다.
- 상태·라벨 표현: 상태 배지 없음. 각주로 "최초 공고 기준 값", "특별공급 미달 시 일반공급 세대수가 바뀐다", "여러 업체면 하나만 표시" 같은 **값의 한계**를 표 바로 아래 밝힌다. 출처는 "○○일 ○○신문 게재 공고문" 형태로 기준일과 매체를 같이 적는다.
- 필터·정렬: 없음.
- 용어 처리: 표 각주에서 한 줄 정의("주택형 = 주거전용면적, 타입 포함")를 붙인다. 해당지역/기타지역, 특별공급 유형(다자녀·신혼부부·생애최초·청년·노부모·신생아·기관추천·이전기관)은 설명 없이 열 이름으로만 나온다.
- 모바일에서 달라지는 것: 같은 표를 그대로 쓰고 넓은 표 앞에 "좌우로 밀어서 보라"는 안내 한 줄을 넣는다. 글자 크기만 커진다.
- 우리에게 쓸 만한 패턴:
  - 상세 순서를 **어디·몇 세대 → 일정 → 공급 구성 → 금액 → 원문**으로 고정한다(공식 원천과 같은 순서라 사용자가 공고문과 대조하기 쉽다).
  - 일정은 단계(특공·1순위·2순위·발표·계약)를 행으로 둔 표 하나로 모은다. 우리는 여기에 D±와 "지금 단계" 표시만 더하면 된다.
  - 금액 표는 단위를 표 머리에 한 번만 적고, "최고가 기준"처럼 **어떤 값인지 기준을 열 이름에 넣는다**.
  - 값의 한계(최초 공고 기준, 바뀔 수 있음)를 그 표 바로 아래 각주로 붙인다 — 출처·라벨을 본문과 떨어뜨리지 않는 방법.
  - 원문(공고문) 링크를 상세 맨 위 한 곳에 버튼으로 둔다.
- 우리에게 맞지 않는 것과 이유: 계약금·중도금을 상세에서 빼고 PDF로만 넘기는 것(우리 persona의 "얼마 필요한가"에 답하지 못한다), 소수 4자리 면적·모델번호 같은 행정용 열을 1단 표에 섞는 것, 인쇄 버튼 중심 팝업 구조.

## 청약홈 — 경쟁률 팝업 (https://www.applyhome.co.kr/ai/aia/selectAPTCompetitionPopup.do?houseManageNo=…&pblancNo=…, 관찰일 2026-10-14, evidence_id applyhome-competition-rea-desktop(접수 종료·미달 단지) · applyhome-competition-desktop · applyhome-competition-full(접수 중 단지))
- 첫 화면에서 가장 먼저 보이는 것 3개: 위 한 줄 안내(미달이면 다음 순위로 넘어간다는 규칙), 주택형별 묶음 표, 오른쪽 당첨가점 최저·최고·평균 열
- 정보 계층: 1단 = 청약결과 열의 상태 문장(접수 중 / 접수 종료) → 2단 = 순위내 경쟁률(또는 미달 세대수) → 3단 = 순위·지역별 접수 건수, 당첨가점, 각주
- 묶음 단위: 주택형 하나 = 행 4개(1순위·2순위 × 해당지역·기타지역)를 병합 셀로 묶은 표.
- 숫자 표기: 경쟁률 열 제목에 "(미달 세대수)"를 같이 적고, 미달이면 **삼각형 기호 + 모자란 세대수**를 괄호로 표시한다. 당첨가점은 최저·최고·평균 3값.
- 상태·라벨 표현: 결과가 아직 없으면 빈칸 대신 "당첨자 발표일 이후 공개", 상태는 "청약 접수중"/"청약 접수 종료" 같은 텍스트로 셀에 쓴다(색 배지 아님). 값이 없는 칸은 "-".
- 용어 처리: 각주에서 "당첨가점은 가점제 당첨자만 집계", "경쟁률은 추첨 전까지 바뀔 수 있어 참고용"을 밝힌다. 해당지역 우선공급 규칙은 별도 버튼으로 연다.
- 모바일에서 달라지는 것: 관찰하지 않음(팝업, 데스크톱만 캡처).
- 우리에게 쓸 만한 패턴:
  - 경쟁률이 없을 때 **언제 공개되는지**를 빈칸 자리에 쓴다("발표일 이후 공개" 형). 우리 "확인 불가(사유)"의 사유 문구 예시로 쓸 수 있다.
  - 미달은 경쟁률과 같은 칸에 다른 표기(기호+세대수)로 넣고, 열 제목에 두 의미를 모두 적는다 — 단, 우리는 기호만 쓰지 말고 "미달 N세대" 텍스트로.
  - 당첨가점은 최저·최고·평균을 한 묶음으로 보여주고 "가점제 당첨자만"이라는 집계 범위를 붙인다.
- 우리에게 맞지 않는 것과 이유: 삼각형 기호만으로 미달을 표시(초보자는 뜻을 모른다), 순위×지역 4행 병합 표(정보는 정확하나 한눈에 "몇 대 1"이 안 보인다).

- 첫 화면에서 가장 먼저 보이는 것 3개: 연도와 월 탭 줄(이번 달 강조) + "오늘" 버튼, 공급유형 필터 칩 줄(특별공급·1순위·2순위·무순위·임의공급·재공급 등), 월간 달력(평일 5열)
- 정보 계층: 1단 = 오늘 칸 표시 → 2단 = 날짜 칸 안 단지명 칩(단계별 색 + 한 글자 표식) → 3단 = 칩 클릭 시 공고
- 묶음 단위: 달력 격자. 탭(공급유형 / 공급지역)으로 필터 방식을 바꾼다.
- 숫자 표기: 날짜만. 하루에 단지가 많으면 칸이 세로로 길어진다(말줄임으로 단지명 자름).
- 상태·라벨 표현: **단계 구분을 색만이 아니라 칩 앞의 한 글자 표식(특·1·2·무·임·불·공·오)으로도** 한다. 오늘 칸에 "TODAY" 텍스트. 공휴일 이름을 칸에 적는다.
- 필터·정렬: 기본 = 이번 달, 아파트의 전 단계 켜짐. 칩을 끄고 켜는 토글.
- 용어 처리: 없음(무순위·임의공급 등 설명 없음).
- 모바일에서 달라지는 것: 관찰하지 않음.
- 우리에게 쓸 만한 패턴:
  - 일정 단계(특공·1순위·2순위·발표·계약)를 색 + **짧은 텍스트 표식**으로 함께 표시한다(D7 "라벨은 색이 아닌 텍스트" 규칙과 맞음).
  - 달력·목록 어디서든 "오늘" 기준을 눈에 보이게 표시한다.
- 우리에게 맞지 않는 것과 이유: 한 글자 표식만으로는 초보자가 뜻을 모른다(범례가 필터 칩에만 있다). 하루에 10개 넘는 칩이 쌓여 읽기 어렵다.

## 청약홈 — 주택청약 용어설명 (https://www.applyhome.co.kr/ar/ard/selectSubscriptVocabularyView.do, 관찰일 2026-10-14, evidence_id applyhome-glossary-desktop — Playwright 보조만)
- 첫 화면: 안내 상자, 분류 탭(전체·청약주택·청약통장·청약자격·청약지역·기타), "용어 | 관련 법률" 2열 표
- 정보 계층: 용어 이름과 근거 법 조문이 먼저, 뜻은 용어 링크를 눌러야 열린다.
- 용어 처리: **별도 용어집 페이지**에 분류 탭으로 모았다. 목록·상세 화면의 용어에서 이 페이지로 바로 가는 연결은 보지 못했다(상세 표의 열 이름은 링크가 아님).
- 우리에게 쓸 만한 패턴: 용어집을 분류(주택·통장·자격·지역)로 나누는 것, 정의마다 근거(법 조문)를 붙이는 것 — 우리 출처 표기 원칙과 같은 방향.
- 우리에게 맞지 않는 것과 이유: 용어가 쓰이는 자리와 정의가 떨어져 있다. 초보자는 상세 화면에서 바로 뜻을 봐야 한다(툴팁·괄호 설명이 필요).

## 사이트 요약 (Tier 1 종합용)
- 요약 우선 배치: 홈만 요약 우선(오늘 접수 N건 카드). 목록·상세는 폼·표가 먼저다.
- 상태 배지: 목록에 없음. 경쟁률 팝업은 상태를 텍스트 문장으로, 캘린더는 색+한 글자 표식으로.
- 일정: 상세에서 단계×지역 표로 가장 정확하다. D-day 없음.
- 필요한 돈: 주택형별 최고가 공급금액만(만원 단위). 계약금·중도금 비율 없음 → 원문 PDF.
- 경쟁률·가점: 별도 팝업. 미달을 기호로 표시, 당첨가점 최저·최고·평균, 발표 전에는 "발표 후 공개" 문구.
- 용어: 별도 용어집 + 표 각주의 한 줄 정의. 인라인 툴팁 없음.
- 출처: 공고문 게재일·매체를 각주에 쓰고, "원문이 우선" 고지를 목록 위에 고정.

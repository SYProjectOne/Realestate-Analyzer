## GH — 홈 (https://apply.gh.or.kr/co/coa/selectMainView.do, 관찰일 2026-10-14, evidence_id gh-home-rea-desktop · gh-home-desktop · gh-home-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개(크기·위치 순):
  1. 왼쪽 큰 기관 슬로건 문장
  2. 오른쪽 "청약공고" 패널: 분류 탭(전체·임대주택·임대상가·매입임대) + 공고 카드 2장(유형 배지 + 공고명 2줄 + 신청기간 줄) + 이전/목록/다음 버튼
  3. 원형 아이콘 5개(청약신청·청약연습·당첨결과 조회·서류제출 대상 조회·지도로 집 찾기)와 하단 "빠른 서비스" 띠
- 정보 계층: 1단 = 슬로건(정보 없음) → 2단 = 최신 공고 카드 2장 → 3단 = 기능 아이콘, 공지사항
- 묶음 단위: 탭 + 카드 캐러셀, 아이콘 버튼 줄, 오른쪽 고정 빠른 메뉴(자가진단 등).
- 숫자 표기: 공고 카드의 신청기간 줄이 **날짜 없이 물결표만** 남은 상태로 보였다(상시 모집 공고로 보임). 기간 아래 빈 막대가 있다.
- 상태·라벨 표현: 공고 카드 머리에 유형 배지(채운 사각 텍스트). 접수 상태 배지는 카드에 없다.
- 필터·정렬: 패널 탭 4개, 기본 "전체".
- 용어 처리: 없음. 오른쪽 빠른 메뉴에 "자가진단"(자격 확인) 입구.
- 모바일에서 달라지는 것: 슬로건·아이콘이 세로로 쌓이고 공고 패널이 아래로 밀린다(`gh-home-mobile`).
- 우리에게 쓸 만한 패턴:
  - 최신 공고를 카드 2장 + "목록" 버튼으로 홈에 노출 — 카드 = 유형 배지 + 이름 + 기간 3요소.
  - 자격 자가진단을 홈 빠른 메뉴에 둔다(청약홈의 "내 청약 준비"와 같은 역할 — 두 곳에서 반복).
- 우리에게 맞지 않는 것과 이유: 첫 화면 절반을 정보 없는 슬로건이 차지, 값이 빈 기간 줄을 그대로 노출(우리는 "확인 불가(사유)"로 바꿔야 한다).

## GH — 목록: 청약공고(임대주택) (https://apply.gh.or.kr/sb/sr/sr7150/selectPbancRentHouseList.do, 관찰일 2026-10-14, evidence_id gh-list-rea-desktop · gh-list-desktop · gh-list-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. 페이지 제목 + 분류 탭 3개(임대주택·임대상가·매입임대)
  2. 필터 상자(지역·유형·상태 드롭다운, 공고명 입력, 큰 검색 버튼)
  3. "총 N건 · 페이지 1/26"과 표 첫 행(데스크톱에서는 첫 행만 보인다)
- 정보 계층: 1단 = 총 건수 → 2단 = 표(번호·유형·공고명·지역·첨부·게시일·마감일·**상태**·**경쟁률**·조회수) → 3단 = 공고명 → 상세, 경쟁률 "확인" 버튼 → 팝업
- 묶음 단위: 표. 경쟁률은 청약홈처럼 셀 안 버튼으로 미룬다.
- 숫자 표기: 날짜 YYYY-MM-DD, 조회수는 쉼표 없는 정수. 값이 없으면 "-".
- 상태·라벨 표현: 상태 열은 텍스트(접수마감 등). 상시 공고는 마감일·상태가 모두 "-". 상태 필터 기본값이 "전체"라 첫 페이지가 마감된 공고로 차 있었다(첫 10행 중 9행이 접수마감).
- 필터·정렬: 기본 = 전 지역·전 유형·전 상태, 10건씩, 최신 게시일 순.
- 용어 처리: 없음(행복주택·장기전세·국민임대·통합공공임대 등 유형명을 그대로).
- 모바일에서 달라지는 것: 필터가 세로 1열로 쌓여 첫 화면의 대부분을 차지. **표는 카드로 바뀌지 않고 그대로 줄어들어** 마감일·상태·경쟁률 열이 화면 오른쪽 밖으로 잘린다(`gh-list-mobile`).
- 우리에게 쓸 만한 패턴:
  - 상태 열 + 경쟁률 "열기" 버튼을 목록에 함께 둔다(청약홈·GH 두 곳에서 반복: 경쟁률은 목록에서 펼치지 않고 버튼으로).
- 우리에게 맞지 않는 것과 이유: 상태 기본값 "전체"(초보자가 첫 화면에서 마감 공고만 보게 된다 — LH처럼 "지금 유효한 것" 기본값이 낫다), 모바일에서 상태 열이 잘려 안 보이는 표(반례: LH 모바일 카드), 조회수 열.

## GH — 상세: 청약공고 (https://apply.gh.or.kr/sb/sr/sr7150/selectPbancDetailView.do?pbancNo=…&pbancKndCd=…, 관찰일 2026-10-14, evidence_id gh-detail-rea-desktop · gh-detail-full · gh-detail-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. "상세정보" 2열 표: 공고명 / **공고상태(텍스트)** · 유형 / 공고일 / 공고문 파일(HWP·PDF, 파일 크기까지 표시)
  2. "공급정보" 머리 띠(지구명, 강조색 가로 막대)
  3. 공급정보 2×3 표(지구명·소재지·전용면적 범위·모집호수·난방방식·입주예정월)
- 정보 계층(위→아래): 1단 = 상태·유형·공고일·원문 파일 → 2단 = 공급정보 요약 표 → 평면도(주택형별 세로 탭 + 이미지) → **주택형 안내 표**(주택형·전용면적·금회공급 세대수·임대보증금·월임대료·인터넷청약 상태) → 안내사항 상자 → **공급일정 글머리**(온라인 접수·현장 접수 기간[시각까지], 서류 제출 대상 발표, 서류 제출 기간, 당첨자 발표 — 모두 시각까지) → 접수처 표 → 3단 = 기타사항, 공통 안내(인증서 준비 등)
- 묶음 단위: 2열 정의 표, 세로 탭(평면도), 가로 표(주택형), 글머리 일정. 아코디언 없음.
- 숫자 표기: 면적은 소수 4자리 ㎡, 범위 "최소 ~ 최대". 일정은 "YYYY.MM.DD HH:MM ~ YYYY.MM.DD HH:MM".
- 필요한 돈 표시: 주택형 표에 보증금·월임대료 열이 있으나 **값 자리에 "공고문 확인" 텍스트**. 금액은 원문으로만.
- 상태·라벨 표현: 공고상태를 상세 첫 표 둘째 행에, 주택형별 인터넷청약 상태를 표 마지막 열에 텍스트로. 평면도 아래 "이해를 돕기 위한 이미지로 실제와 다를 수 있음" 각주. **난방방식 칸은 값 없이 빈칸**.
- 필터·정렬: 없음.
- 용어 처리: 주택형 표 위 2줄 안내("주택형을 누르면 세부 공급정보", "인터넷 신청 가능 여부는 공고문 확인"). 용어 정의는 없다.
- 모바일에서 달라지는 것: 2열 표가 그대로 좁아진다(빈 난방방식 칸도 그대로). 평면도 세로 탭이 가로 탭 줄로 바뀐다. 별도 요약 카드 없음(`gh-detail-mobile`).
- 우리에게 쓸 만한 패턴:
  - 상세 첫 표에 **상태·공고일·원문 파일**을 같이 둔다(LH·청약홈과 같은 1단 구성 — 공공 3곳 반복).
  - 일정을 **단계: 시작~끝(시각까지)** 글머리로 한 블록에 모은다(접수 → 서류 대상 발표 → 서류 제출 → 당첨 발표).
  - 금액을 화면에 못 줄 때 빈칸 대신 "원문에서 확인" 텍스트(우리 "확인 불가(사유)"와 같은 방향).
  - 원문 파일에 형식·크기를 붙여 "누르면 무엇이 열리는지" 알린다.
- 우리에게 맞지 않는 것과 이유: 값이 빈 칸을 그대로 둠(난방방식) — D7 빈 값 규칙 위반 사례, 평면도 이미지 블록이 금액·일정보다 위에 와서 핵심을 아래로 민다, 소수 4자리 면적.

## 사이트 요약 (Tier 1 종합용)
- 요약 우선 배치: 상세 첫 표에 상태·원문이 먼저 온다. 홈·목록은 요약보다 슬로건·필터가 먼저.
- 상태 배지: 목록·상세 모두 텍스트 상태(접수마감, 상시는 "-"). 기본 필터 "전체"라 마감 공고가 먼저 보인다.
- 일정: 단계별 시작~끝을 시각까지 쓴 글머리 블록. D-day 없음.
- 필요한 돈: 보증금·월임대료 열은 있으나 값은 "공고문 확인".
- 경쟁률·가점: 목록의 "확인" 버튼 → 팝업(이번에 열지 않음).
- 용어: 없음(자가진단 입구만).
- 출처: 원문 파일(형식·크기 표시)을 상세 첫 표에.
- 관찰 한계: 분양 공고는 이 도메인에서 확인 못 함 → "경기 공공분양 정보 배치"는 관찰 불가(이 사이트 범위 밖).

## LH청약플러스 — 홈 (https://apply.lh.or.kr/lhapply/main.do, 관찰일 2026-10-14, evidence_id lh-home-rea-desktop · lh-home-desktop · lh-home-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개(크기·위치 순):
  1. **화면 가운데를 덮는 홍보 팝업**(단지 분양 광고 슬라이드 9장, "오늘 열지 않기"/"닫기") — 본문을 가린다.
  2. 팝업 뒤 큰 인사 문구와 메뉴 카드(청약 / 선착순 계약 / 지도 / 고객서비스)
  3. 오른쪽 "오늘의 청약 일정" 패널: 접수 N건, 당첨·낙찰자 발표 N건을 주택 종류(임대·분양·토지·상가)별로 나눈 숫자 타일
- 정보 계층: 1단 = (팝업) → 메뉴 진입 카드 → 2단 = 오늘 접수·발표 건수 타일 → 3단 = 주택 종류별 바로가기 줄
- 묶음 단위: 카드(메뉴), 2×2 숫자 타일(오늘 일정), 오른쪽 고정 빠른 메뉴(로그인·증명서·예비입주자 순위 등).
- 숫자 표기: "N건" 정수. 기준은 "오늘"이라는 제목뿐.
- 상태·라벨 표현: "접수" / "발표" 두 묶음 제목이 곧 상태다. 0건도 숨기지 않고 "0건"으로 보인다.
- 필터·정렬: 없음.
- 용어 처리: 홈에는 없음. 팝업 광고 안에 "계약금 10%·중도금 없음·유주택자 가능" 같은 **조건을 아이콘+짧은 말 4칸으로 요약한 카드**가 있다(광고 이미지라 접근성 텍스트 없음).
- 모바일에서 달라지는 것: 하단 탭바(홈·청약·사전청약·지도·MY)로 바뀐다. 팝업은 그대로 뜬다.
- 우리에게 쓸 만한 패턴:
  - 청약홈과 같은 "오늘 접수 N / 오늘 발표 N" 숫자 타일 — **두 공공 사이트가 같은 1단 구성을 쓴다**(검증된 패턴 후보).
  - 0건도 지우지 않고 "0건"으로 보여주는 것(빈 상태를 숨기지 않는다).
  - 조건 요약을 "계약금 비율 / 중도금 유무 / 신청 가능 대상 / 지역 제한" 4칸으로 나누는 발상 — 우리 G3 "필요한 돈·자격" 요약 칸 구성에 참고. 단 우리는 이미지가 아닌 텍스트로, 공고 원문 값만으로.
- 우리에게 맞지 않는 것과 이유: 본문을 덮는 광고 팝업(첫 3초를 광고가 차지한다), 이미지 안에만 있는 핵심 조건(읽기 보조기·검색·복사 불가), 가격이 싸다는 식의 판매 문구(근거 없는 추천과 같은 성격).

## LH청약플러스 — 목록: 분양주택 공고문 (https://apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancList.do?mi=1027, 관찰일 2026-10-14, evidence_id lh-list-rea-desktop · lh-list-desktop · lh-list-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. 페이지 제목 + 경로(왼쪽 세로 메뉴: 공고문·분양가이드·청약연습·청약신청·자격확인)
  2. 필터 상자(유형 / 지역 / 상태 / 기간[게시일 기준, 기본 최근 2개월] / 공고명)
  3. 안내 한 줄("상태 기본값이면 공고중·정정공고중·접수중이 모두 나온다") + "전체 N건" + 표 첫 2행
- 정보 계층: 1단 = 전체 건수 → 2단 = 표(번호·유형·공고명·지역·첨부·게시일·마감일·**상태**·조회수) → 3단 = 공고명 클릭 시 상세, 첨부 아이콘 클릭 시 파일
- 묶음 단위: 데스크톱 표 / 모바일 카드.
- 숫자 표기: 날짜 YYYY.MM.DD, 조회수 천 단위 쉼표. D-day 없음.
- 상태·라벨 표현: **상태 열이 따로 있다**(공고중 / 접수중 / 정정공고중 등). 데스크톱은 색 글자, 모바일은 채운 알약 배지(공고중과 접수중이 다른 색). 상태 필터의 기본값이 "지금 유효한 것만"이고, 그 뜻을 필터 아래 한 줄로 풀어 쓴다. 정정 공고는 제목 앞 대괄호 표식.
- 필터·정렬: 기본 = 상태 "공고중", 기간 최근 2개월, 한 페이지 50건(선택 가능). 모바일은 공고명 입력 하나만 보이고 나머지는 "상세" 펼침으로 접힌다.
- 용어 처리: 없음(무순위·선착순·신혼희망 등 유형명을 그대로 쓴다). 왼쪽 메뉴에 "분양가이드"가 항상 보인다.
- 모바일에서 달라지는 것: 표 → **카드**. 카드 한 장 = 위에 알약 배지 줄(유형·지역·상태·첨부 아이콘) + 아래 공고명 2줄. 게시일·마감일·조회수는 카드에서 빠진다. 필터는 1칸 + "상세" 펼침.
- 우리에게 쓸 만한 패턴:
  - 목록에 **상태 열**을 두고, 기본 필터를 "지금 넣을 수 있거나 곧 열리는 것"으로 둔 뒤 그 뜻을 한 줄로 밝힌다(G2).
  - 모바일 목록은 표를 카드로 바꾸고, 카드 머리에 텍스트 배지(유형·지역·상태)를 한 줄로 모은다(D7 텍스트 배지 규칙과 맞음).
  - 모바일 필터는 핵심 1칸만 두고 나머지는 펼침으로 접는다.
- 우리에게 맞지 않는 것과 이유: 조회수 열(판단 근거로 오해될 수 있다), 모바일 카드에서 마감일이 빠지는 것(우리 persona에게 가장 중요한 값이다).

## LH청약플러스 — 상세: 공고문 (https://apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancInfo.do?panId=…&mi=1027, 관찰일 2026-10-14, evidence_id lh-detail-rea-desktop · lh-detail-full · lh-detail-mobile)
- 첫 화면에서 가장 먼저 보이는 것 3개:
  1. 옅은 색 머리 띠 안의 공고명
  2. 바로 아래 **메타 한 줄 묶음: 공고상태(접수중, 색 글자) · 공고일 · 마감일 · 유형 · 담당부서 · 문의처**
  3. 강조 배경 상자의 원문 파일(공고문 HWPX·PDF) + 바로보기·점자뷰어·점자음성 버튼, 그 아래 첨부(팸플릿·위임장)
- 정보 계층(위→아래): 1단 = 상태·날짜 메타 + 원문 파일 → **"공고내용" 글머리 요약 9줄**(누가 신청 가능한지, 무엇이 면제되는지, 추첨 방식, 옵션, **분양대금 구성(중도금 없이 계약금+잔금, 대출 알선 없음)**, 신청 준비물(인증서), 추가 자료 위치, 문의처) → 2단 = 공급정보 요약 카드(소재지·전용면적 범위·총 세대수·난방·입주예정월) → 단지 이미지 탭(토지이용·위치·배치·조감·동호배치) → 위치 지도 → 단지 특장점 표 → **주택형 안내 표**(주택형·전용면적·세대수·금회 공급 세대수·평균 분양가(원)·청약신청·상세보기) → **공급일정 표**(구분·신청 일시·방법) + 당첨자 발표일·서류 제출 기간·계약 기간 줄 → 접수처 정보·지도 → 3단 = 기타사항, 관심공고 등록
- 묶음 단위: 메타 줄(정의 목록), 요약 글머리, 요약 카드 1장, 이미지 탭, 표 2개, 지도 2개. 아코디언 없음, 세로 한 페이지.
- 숫자 표기: 평균 분양가는 **원 단위 전체 숫자**(9자리, 쉼표). 면적은 소수 2자리 ㎡, 범위는 "최소 ~ 최대". 신청 일시는 시각까지(10:00 ~ 17:00). 입주예정은 "YYYY년 MM월".
- 필요한 돈 표시: 주택형별 **평균** 분양가 한 값 + 요약 글머리에서 대금 구조(계약금·중도금·잔금 유무, 대출 알선 여부)를 문장으로. 계약금 금액·비율 숫자는 이 화면 본문에 없다(공고문·팸플릿으로).
- 상태·라벨 표현: 상태를 메타 줄 첫 칸에 텍스트로. 단지 특장점 칸이 비어 있을 때 "최초 공고와 팸플릿 참조"처럼 **어디서 확인할지**를 적는다. 이미지에는 "소비자 이해를 위한 것으로 실제와 다를 수 있음" 각주.
- 필터·정렬: 없음.
- 용어 처리: 요약 글머리가 **공고문 핵심 조건을 쉬운 문장으로 다시 쓴 것**이다(유주택자 신청 가능, 재당첨 제한 미적용 등 괄호 보충). 표 열 이름은 전문 용어 그대로(금회공급, 무순위). 주택형 표 위에 "자격 사전확인" 버튼.
- 모바일에서 달라지는 것: 메타가 2열 글머리로, 원문 파일 버튼이 줄바꿈되어 첫 화면을 거의 다 차지한다. 요약 글머리는 첫 화면 아래로 밀린다. 하단 탭바 고정.
- 우리에게 쓸 만한 패턴:
  - 상세 맨 위에 **상태·공고일·마감일을 한 줄 메타**로 묶는다(G3 1단). 우리는 여기에 D±를 붙인다.
  - 원문(공고문) 파일을 메타 바로 아래 **눈에 띄는 상자 하나**에 모은다 — 출처를 숨기지 않으면서 본문과 분리.
  - 공고 핵심 조건을 **5~9줄 글머리 요약**으로 표 앞에 둔다. 우리는 이 자리에 API가 준 공고 필드(자격·대금 구조·일정)만 쓰고 문장을 새로 지어내지 않는다.
  - 대금 구조(계약금·중도금·잔금 유무, 집단대출 알선 여부)를 숫자 표와 별개로 한 줄 문장으로 알려 준다 — persona의 "얼마 필요한가" 질문에 가장 직접 답하는 자리.
  - 일정은 신청 단계 표 + 그 뒤 단계(발표·서류·계약)를 날짜 범위 줄로 잇는다.
  - 빈 칸 대신 "어디서 확인할지"를 적는다(우리 "확인 불가(사유)"와 같은 방향).
- 우리에게 맞지 않는 것과 이유: 평균 분양가를 원 단위 9자리로 그대로(초보자는 "억·만"으로 읽어야 빠르다 — 우리는 FactCell이 억·만 포맷), 지도 2개·이미지 탭이 표보다 위에 와서 가격·일정을 아래로 밀어내는 순서, 상세 안의 "청약신청하기" 버튼(우리 범위 밖).

## LH청약플러스 — 분양가이드 (https://apply.lh.or.kr/lhapply/cm/cntnts/cntntsView.do?mi=1178&cntntsId=1048, 관찰일 2026-10-14, evidence_id lh-guide-rea-desktop)
- 첫 화면에서 가장 먼저 보이는 것 3개: 주택 유형 탭 3개(공공분양 / 신혼희망타운 / 이익공유형), 그 아래 주제 칩 5개(소개 · 분양절차 · 신청자격-일반공급 · 신청자격-특별공급 · 전매제한 등 안내), "○○이란?" 질문형 제목과 한 문단 정의
- 정보 계층: 1단 = "이게 뭔가"(질문형 제목 + 한 문단) → 2단 = 분류(주택 종류, 공급 유형) 정의 목록 → 3단 = 절차·자격·전매제한 칩으로 이동
- 묶음 단위: 상단 탭(유형) × 칩(주제) 2단 내비게이션. 본문은 제목 + 짧은 정의 목록.
- 용어 처리: **질문형 제목("~란?")과 한 문장 정의**, 정의는 대상·조건(예: 전용 85㎡ 이하)을 괄호로 붙인다. 전매제한·자격처럼 초보자가 막히는 주제를 칩으로 따로 뺐다.
- 모바일에서 달라지는 것: 관찰하지 않음.
- 우리에게 쓸 만한 패턴:
  - 용어·제도 설명을 "무엇인가 / 절차 / 자격 / 제한(전매·거주)" 4~5주제로 나누고, 질문형 제목으로 시작한다(우리 용어 도움말 구조).
  - 상세 화면 왼쪽 메뉴에 가이드가 늘 보이게 둔다(목록·상세에서 한 번에 닿는다).
- 우리에게 맞지 않는 것과 이유: 유형별 탭이 공공 상품(신혼희망·이익공유) 기준이라 우리(민간분양 중심)와 축이 다르다.

## 사이트 요약 (Tier 1 종합용)
- 요약 우선 배치: 상세에서 **메타 한 줄 + 원문 상자 + 핵심 조건 글머리**가 표보다 먼저 온다. 홈은 광고 팝업이 요약을 가린다.
- 상태 배지: 목록 상태 열(공고중·접수중·정정공고중), 모바일은 채운 알약 배지. 기본 필터 = 유효한 공고만.
- 일정: 신청 일시(시각까지) 표 + 발표·서류·계약 날짜 줄. D-day 없음.
- 필요한 돈: 평균 분양가(원 단위) + 대금 구조 문장(중도금 유무·대출 알선 여부).
- 경쟁률·가점: 상세에 없음(이번 관찰 범위 밖 — 결과 조회는 로그인 영역).
- 용어: 별도 분양가이드(질문형 제목·주제 칩) + 상세 요약 글머리의 쉬운 문장.
- 출처: 원문 파일을 상세 상단 강조 상자에 고정, 빈 칸에 "어디서 확인할지".

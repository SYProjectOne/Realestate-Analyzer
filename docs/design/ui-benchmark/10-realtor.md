## Realtor.com — 신축 홈 (https://www.realtor.com/newhomes, 관찰일 2026-10-14, evidence_id realtor-newhomes-desktop)

- 첫 화면에서 가장 먼저 보이는 것 3개: (1) 큰 제목(신축 사이트맵), (2) 주(state)별 소제목, (3) 소제목 아래 도시 링크 2열 목록. 신축 "주택"과 신축 "단지"가 별도 목록으로 나뉜다.
- 정보 계층: 1단 지역(주) → 2단 도시 링크 → 3단 단지 목록 페이지.
- 묶음 단위: 텍스트 링크 목록. 카드나 숫자는 없다.
- 숫자 표기·상태·필터·용어: 해당 없음.
- 우리에게 쓸 만한 패턴: "개별 세대"와 "단지" 단위를 구분해서 들어가게 한다. 우리는 단지 단위가 기본이다.
- 맞지 않는 것: 검색엔진용 링크 나열 페이지라 사용자 화면으로 참고할 것이 적다.

## Realtor.com — 도시별 신축 단지 목록 (https://www.realtor.com/newhomecommunities/Woodbury_MN, 관찰일 2026-10-14, evidence_id realtor-list-desktop)

- 첫 화면에서 가장 먼저 보이는 것 3개: (1) 화면 위 1/3을 차지하는 프로모션 배너(남은 기간 카운트다운), (2) 검색창, (3) "○○의 신축 단지" 제목 + 단지 수.
- 정보 계층:
  - 1단: 단지 수(6개)와 정렬(최신순).
  - 2단: 단지 카드 = 시공사(작게, 맨 위) / 주소 / "단지" 유형 라벨 / **"부터 $가격"** / 방 범위·욕실 범위 / 단지명 / 시공사 문의 버튼.
  - 3단: 반경 확장 결과("주변 ○마일 ○개 단지").
- 묶음 단위: 카드 그리드. 결과가 적으면 반경을 넓힌 결과를 이어서 붙인다(빈 화면이 생기지 않음).
- 숫자 표기: 단지 단위 가격은 최저가 "부터"로만 쓴다. 방·욕실은 "3-4"처럼 범위로 쓴다.
- 상태·라벨 표현: 카드 위에 혜택 배지(금리 인하 등)와 투어 가능 배지가 붙는다.
- 필터·정렬: 인기 필터 칩. 정렬 기본값은 최신 등록순.
- 용어 처리: 목록 위에 **"프로모션 설명" 링크(물음표 아이콘)**. 배지 용어를 한곳에서 풀어 준다.
- 모바일: 관찰 못 함.
- 우리에게 쓸 만한 패턴:
  - 단지 카드의 가격은 "최저 ○억부터" 또는 범위로 쓰고, 평형은 범위로 쓴다.
  - 결과가 적을 때 범위를 넓힌 결과를 따로 묶어 "주변 ○개"로 구분해서 붙인다. 우리는 지역이 사용자 입력이라 자동 확장은 하지 않는다. 대신 "인접 지역으로 바꿔 보기" 안내를 빈 상태에 둔다.
  - 배지가 여럿이면 목록 위에 "배지 설명" 링크 하나로 용어를 모은다. 우리 LabelBadge(추정·비공식·재가공·확인 불가·사람 확인) 설명 진입점으로 쓴다.
- 맞지 않는 것과 이유: 카운트다운 프로모션 배너, 혜택 배지, 시공사 문의 버튼(영업 유도).

## Realtor.com — 단지 상세 (https://www.realtor.com/community-detail/Westwind-Colonial-Manor-Collection_…, 관찰일 2026-10-14, evidence_id realtor-community-desktop)

- 첫 화면에서 가장 먼저 보이는 것 3개: (1) 상단 광고 배너와 사진 캐러셀(프로모션 이미지), (2) 오른쪽 연락처 입력 폼(이름·이메일·전화), (3) 사진 아래 "입주 가능 / 건축 예정" 라벨이 붙은 사진 2장. 단지명과 가격은 첫 뷰포트 밖에 있다.
- 정보 계층(접근성 트리 순서):
  - 1단(요약): 단지명 → **"부터 $가격"** → 예상 월 상환액(버튼, 누르면 계산기) → 분양사무소 주소 → 시공사 → 핵심 수치 4개(방 범위, 욕실 범위, **입주 가능 세대 수, 건축 예정 세대 수**).
  - 2단: 견학 날짜 고르기 → "입주 가능 세대" 목록(가격·방·면적·주소·평당가) → "건축 예정 평면" 목록(평면명·부터 가격·평면도 보기·평당가).
  - 3단: 특징, 사무소 운영 시간(요일별 표), **월 비용 분해**(원리금·재산세·보험·관리비·모기지보험, 계약 시 필요 금액 = 계약금 20% + 예상 부대비용 4%), 금리 기준과 고지, 학교, 동네.
- 묶음 단위: 상태별 목록(입주 가능 vs 건축 예정), 접는 패널(월 비용), 탭(금리 종류 3개).
- 숫자 표기:
  - 단지 가격은 "부터 최저가". 세대별로는 정확한 금액과 평당가.
  - 월 비용은 총액(큰 글씨) 아래에 항목별로 나누고, 계약 시 필요 금액을 "계약금 + 부대비용"으로 나누며 각각 비율(%)을 붙인다.
  - 계산에 쓴 금리 기준(30년 고정 평균, 기준일)을 별표 각주로 밝히고, 이름이 붙은 고지 버튼을 둔다.
- 상태·라벨 표현: 세대 상태를 "입주 가능 / 건축 예정" 두 묶음으로 나누고 묶음마다 개수를 쓴다. 판매 상태는 각 행에 텍스트로 쓴다.
- 필터·정렬: 없음.
- 용어 처리: 보훈 혜택 옵션 옆에 정보 아이콘 툴팁. 월 비용 각 항목은 쉬운 이름.
- 모바일: 관찰 못 함.
- 우리에게 쓸 만한 패턴:
  - **단지 요약 4칸**: 평형 범위 / 가격 범위 / "지금 가능한 것 ○개 vs 예정 ○개". 우리 G3에 공급 유형별 세대수(특별공급 ○, 일반공급 ○)를 같은 방식으로 둔다.
  - **"얼마가 필요한가" 분해 블록**: 총액 → 항목(계약금·중도금·잔금) → 각 비율. 우리는 공고문 값만 보여주고, 금리·대출은 계산하지 않는다(판단 금지). 다만 "계약 시 필요 금액 = 분양가 × 계약금 비율"처럼 공고에 나온 비율을 보여주는 것은 §6 수식 범위 안에서 검토할 수 있다(결정 사항으로 넘김).
  - 계산 기준(금리·기준일)을 숫자 바로 아래 각주로 붙인다. 우리 출처·확인일 규칙과 같다.
- 맞지 않는 것과 이유: 첫 화면을 광고와 연락처 폼이 차지한다. 핵심 정보가 첫 뷰포트 밖이다. 대출 사전승인 유도 버튼. 우리는 이 반대로 단지명·가격·상태를 첫 화면에 둔다.

## 1. 한국부동산원 — 주간 아파트 가격 동향 보도자료 (evidence report-rone-weekly-p1-desktop)

- **첫 장 구성(관찰)**: 표로 짠 머리 상자. 왼쪽 기관 표식, 가운데 큰 "보도자료" 글자, 오른쪽 통계 포털 표식과 주소가 있다. 그 아래 행:
  - 배포 일시와 **총 매수(본문 ○매, 붙임 ○매)**: 이번 호는 총 15매 = 본문 8 + 붙임 7.
  - 담당 부서와 내용 문의(직위·이름·전화 5명).
  - 보도 시점(엠바고): "○월 ○일 ○시 이후 보도".
- 게시판 글 보기에는 본문 텍스트가 없다. 내용은 첨부 PDF·HWPX 두 형식에만 있고, 글 보기에서 "첨부파일 미리보기"를 연다.
- 표 크기, 차트-표 배치, 용어 각주: **관찰 불가(2쪽 이후 미관찰)**. 짐작으로 채우지 않는다.
- 배울 점:
  - **본문/부록 매수를 첫 장에 밝힌다.** 읽는 사람이 "본문 8장만 읽으면 되고 나머지는 표"라는 것을 바로 안다. 우리 보고서 첫 장에 "본문 n쪽 · 부록(표) n쪽"을 둔다.
  - 발행 일시, 기준일(제목의 "(○○기준)"), 문의처를 머리 상자 한곳에 모은다.
  - 같은 내용을 두 형식(PDF·HWPX)으로 낸다. 우리 G8의 HTML·PDF 두 형식과 같은 생각이다.

## 2. KB부동산 — 통계기상도(월간 지수 화면) + KB주택시장 리뷰(월간 해설)

### 2-1 KB통계기상도 (https://data.kbland.kr/weathermap, evidence report-kb-weathermap-desktop)
- **첫 화면**: 왼쪽 패널에 지표 탭 3개(주택가격지수 / 아파트 평균가격 / 전세가율). 그 아래 "지역 · 지표명 + 도움말(?)" 제목과 **지역별 표 1개(열 3: 지역명 / 지수 / 변동률(%) — 변동률 기준 정렬 ▼, 행 = 시도 17개, 첫 화면에 11행)**. 표 아래 "○년 ○월 기준" 선택 상자가 있다. 오른쪽은 전국 지도이고, 시도마다 라벨(지역명 / 지수 / ▲▼ 변동률)을 단다. 위쪽 띠에 주기(월간·주간), 거래(매매·전세), 유형(아파트·단독·연립·종합), 규모 칩이 있다.
- **차트-표 배치**: 지도와 표를 같은 화면에 나란히 두고, 둘 다 같은 숫자를 보여준다. 지도(차트)를 표로 동시에 읽을 수 있다(우리 D7 "차트 데이터는 표로"와 같다).
- **숫자 표기**: 지수는 소수 첫째 자리, 변동률은 소수 둘째 자리. 오르면 ▲, 내리면 ▼를 붙여 **색과 기호를 함께** 쓴다.
- **범례**: 오른쪽 아래에 "지표명 + (단위: %)" 제목과 −4 ~ +4 색 구간 막대가 있고, 구간마다 날씨 아이콘(비 ~ 맑음)을 단다.
- **용어·출처**: 지표명 옆 물음표 도움말. 화면 안에 출처 문장은 없다(사이트 자체가 발행처).
- 주의: 날씨 비유(맑음/비)는 숫자 구간을 좋고 나쁨으로 바꿔 읽게 만든다. 우리 규칙(판단을 UI에서 만들지 않는다)과 맞지 않으므로 **아이콘 비유는 쓰지 않는다**. 단위 붙은 범례와 ▲▼ 기호만 가져간다.

### 2-2 KB주택시장 리뷰 2026년 9월호 (kbthink.com, WebFetch)
- **형식**: 한 호를 7화로 나눈 웹 연재(1화 미리보기 + 매매가격·매매거래·전세·월세·분양·금융). PDF 링크는 없다.
- **첫 장(1화 미리보기)**: 제목·발행일·읽는 시간 다음에 바로 **요약 블록(매매 1문단, 전월세 1문단)**. 결론 문장이 맨 앞에 있고 세부 수치는 뒤 섹션에 있다. 섹션 순서: 매매(가격·거래) → 전월세(전세·월세·거래) → 분양 → 금융.
- **본문(2화 매매가격)**: 제목 아래 **한 줄 부제가 결론**이다. 본문은 "■ 소제목(결론형) → ◯ 지역·원인 → * 세부 수치" 3단 글머리.
- **표**: 0개. 수치는 문장과 차트로만 전달한다.
- **차트**: 4개, 모두 이미지. 각 차트 **위에 제목(지표명 + 기간), 아래에 "자료: 발행 기관" 출처 한 줄과 "확대" 링크**. 단위·기준값은 차트 이미지 안에만 있다.
- **용어**: 본문에는 괄호 설명, 각주, 설명 박스가 없다. 지수 이름을 풀이 없이 쓴다. 사이트 전체 "금융용어사전" 링크는 본문과 연결되지 않는다.
- **기준일**: 발행일과 "○월" 표현뿐이다. 별도 기준일 각주는 없다.

## 3. 부동산R114 — 트렌드 › 리포트 (https://r114.com/trends/report/…, evidence report-r114-report-desktop)
- **형식**: 카드뉴스. 제목 + 날짜 + 이미지 슬라이드 5장 + 관련 읽을거리 6개 + 추천 콘텐츠.
- **첫 장**: 슬라이드 1장이 표지(리포트 종류 배지, 연월, 큰 제목, 지역, 단지명). 텍스트 요약 블록은 없다.
- **표·차트·출처·용어**: 페이지 텍스트(접근성 트리)에는 없다. 모든 내용이 이미지 안에 있어 화면 낭독기, 검색, 복사가 안 된다. 출처·기준일 각주도 텍스트로는 없다(WebFetch로 본 다른 2건도 같음).
- 참고: 사이트 지도에 용어 위키 분류(매매·임대·금융·청약·세금·경매·정책·재건축…)가 있다. 용어 설명은 보고서 밖의 별도 사전으로 운영한다(`10-r114.md` 참고).

**우리 G8에 가져갈 것(검증 수준은 Phase 3에서 다른 노트와 합쳐 매김)**
1. 첫 장 = **결론 요약 블록(2~3문단, 판정기 결과 문장만 인용)** + **메타 상자**(기준일, 발행일, 본문/부록 쪽수, 자료 출처 수, 문의·버전). 근거: KB 리뷰의 요약 우선, 부동산원 머리 상자.
2. **본문과 부록(긴 표)을 나눈다.** 본문에는 요약 표(열 3~4개)만 두고 전체 표는 부록으로 보낸다. 근거: 부동산원 본문/붙임 분리, KB 기상도 3열 표.
3. 차트마다 **위에 제목(지표·기간), 아래에 "자료: 출처 · 확인일" 한 줄**을 붙이고, 같은 숫자의 표를 바로 옆이나 부록에 둔다. 근거: KB 리뷰 차트 각주, 기상도 지도+표 병치.
4. 범례·표 머리에 단위를 쓰고, 증감은 색과 함께 ▲▼(또는 +/−) 기호로 쓴다. 근거: KB 기상도. 날씨 같은 좋고 나쁨 비유는 쓰지 않는다.
5. **용어는 보고서 안에서 해결한다**: 처음 나올 때 괄호로 짧게 풀고 끝에 용어 부록을 둔다. 세 곳 모두 본문 안 용어 설명이 약했다(KB 리뷰 0, R114는 별도 위키, 부동산원은 미관찰). 우리 대상 사용자에게는 이것이 차별점이다.
6. **이미지에만 정보를 넣지 않는다**(R114 카드뉴스의 반례). 모든 수치는 텍스트·표로도 존재해야 출처 라벨과 낭독이 유지된다.

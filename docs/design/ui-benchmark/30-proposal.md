**이 문서는 제안이다. 승인 전에는 코드를 고치지 않는다**(메타 프롬프트 §4 Phase 4). 판단이 갈리는 지점은 §12 "결정 사항"에 모았다.

대상 사용자는 05-persona의 P1~P4다. 이들이 먼저 묻는 질문은 다섯 가지다.
1. 지금 넣을 수 있나, 언제까지인가?
2. 얼마가 필요한가?
3. 언제 팔 수 있나, 꼭 살아야 하나?
4. 주변보다 높은가 낮은가?
5. 믿을 수 있는 값인가?

## 1. 공통 원칙 (모든 제안에 적용)

**정보 계층 정의**
- **1단(결론·요약)**: 스크롤 없이 첫 화면에 보인다. 초보 질문 1~3에 답하는 공식 사실(상태·일정·가격·제한)이다.
- **2단(핵심 수치)**: 같은 화면 아래쪽이나 펼침에 둔다. 가격 갭·점수·확률처럼 계산값과 판정기 결과다.
- **3단(상세·원문)**: 탭·패널·부록에 둔다. 표 전체, 출처 원문, 판정 기록이다.

**바꾸는 것과 바꾸지 않는 것**
- 바꾸는 것: 순서, 묶음, 접기, 이름(문구), 시각적 무게.
- 바꾸지 않는 것: API 값, 라벨, 출처, 확인일, 판정 결과. 프론트는 새 숫자를 계산하지 않는다(규칙 4). 부호를 "높음/낮음" 글자로 바꾸는 표시 매핑과 개수 세기(MetaValue, D25-3)만 한다.
- 모든 수치는 지금처럼 `FactCell`로 그린다. 라벨 글자는 어떤 값에서도 사라지지 않는다(규칙 5). 날짜는 D±를 붙이고, 빈 값은 "확인 불가(사유)"로 쓴다(D7). 하단 "투자 권유 아님 · 상대 비교" 고정 문구는 유지한다.

**문구 금지어**: 새 문구에 쓰지 않는 말이다. 테스트로 검사한다.
- 평가·권유: 추천, 유리, 불리, 좋음, 나쁨, 싸다, 비싸다, 저렴, 알짜, 기회, 사세요, 넣으세요, 당첨 가능
- 과장: 확실, 보장(단, "보장 아님"이라는 부정형 고지는 쓴다)

**근거 등급**: 아래 각 제안에 쓴 패턴은 모두 20-gap의 "검증된" 이상이다. 패턴 ID는 20-gap §1을 따른다.

### 8-3 숨기지 않는다는 증거

원래 사유는 같은 요소의 `title`에 있고(0클릭, 마우스 올림), 출처 패널 "라벨" 줄에도 있다(1클릭). 테스트 세 가지를 둔다.
1. 매핑된 문구가 나온다.
2. `title`에 원 사유가 있다.
3. 모르는 사유는 바뀌지 않는다.

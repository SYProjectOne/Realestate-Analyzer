# 대응표 다시 만들기 지시 (CEO)

목적: 현재 프론트엔드의 기능을 **하나도 빠짐없이** 뽑아, 새 목업 보드의 어느 섹션으로 갔는지 짝짓는다. 이 표가 나중에 구현 체크리스트가 된다(줄마다 테스트 하나).

## 입력
- 현재 소스: `frontend/src/pages/<화면>/` 전체 + 쓰는 `frontend/src/components`, `frontend/src/charts`, `frontend/src/layout`, `frontend/src/app`, 문자열 `frontend/src/i18n/ko.json`
- 목업 보드: `docs/design/ui-benchmark/50-mockup/boards/<Board>.dc.html` (HTML — 섹션 제목·문구를 읽고 위치를 찾는다)

## 뽑을 것 (빠짐없이)
블록/섹션, 버튼, 링크, 폼 입력칸(검증 오류 포함), 필터, 정렬, 토글, 탭, 다운로드, 다이얼로그/팝오버, 키보드 동작, 표의 열(열마다 한 줄), 차트(차트마다 한 줄 + 축·범례·표로 보기), 상태(로딩·오류·빈·저하·재판정 필요·동률·불안정·권한 없음·읽기 전용), 배지, 쓰는 API 호출.

## 출력 파일
`docs/design/ui-benchmark/50-mockup/coverage/coverage-<Board>.md` — 보드마다 하나. 형식:

```markdown
# 대응표 — <현재 화면 이름> → <Board>.dc.html
| # | 기존 기능 (현재 소스 위치 · ko 키/문구) | 새 목업 위치 (보드 · 섹션 제목) | 바뀐 이름 | 상태 |
|---|---|---|---|---|
| 1 | … (`pages/complex/ComplexHeader.tsx` · `page.G3.summary.money` "내야 할 돈") | Detail · "언제, 얼마를 내나요?" | 내야 할 돈 → 언제, 얼마를 내나요? | 있음 |
```
- 상태: `있음` / `문구로만`(그림 없이 설명으로만 있음) / `다른 보드`(보드 이름) / `빠짐`(사유)
- 표 끝에 요약: 전체 n · 있음 n · 문구로만 n · 다른 보드 n · 빠짐 n, 그리고 빠짐 목록.
- 목업에 새로 생긴 것(기존에 없던 것)은 별도 표 "새로 더한 것"으로.

## 규칙
- 보드에 실제로 없는 기능을 "있음"으로 쓰지 않는다. 확인이 안 되면 `빠짐(목업에 없음)`으로 정직하게.
- 이 폴더(`docs/design/ui-benchmark/50-mockup/coverage/`) 밖에 아무것도 쓰지 않는다. 보드·소스 수정 금지. git 명령 금지. 비밀 출력 금지.
- 최종 보고(메인으로): 파일 경로, 보드별 전체/빠짐 개수, 빠짐 목록(한 줄씩). 짧게.

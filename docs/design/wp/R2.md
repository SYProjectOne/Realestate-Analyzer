=====WP7=====
# WP7 스케줄러·변경 감지·파이프라인 — 작업 지시

소유: `backend/app/scheduler/`, `backend/tests/scheduler/`.
참조: RA §3(파생 테이블·스냅샷 규칙), §4-4 잡, §5 WP7 카드, §6-5, §10(스케줄·runbook), §9 T3·T8·T17·T18; meta §2-1(P1~P9 순서), §2-4; DECISIONS D2-4(reference.refresh·region.bootstrap), D6(판정기 버전·모델 변경 → change_event critical + 전체 재판정 1회); `app/worker.py`가 부르는 규약 `app.scheduler.runner.main(argv) -> int`(scheduler README).

## 할 일 — 이 WP가 모든 모듈을 엮는 "접착제"다
1. `jobs.py`: APScheduler — daily 06:00 `collect.daily`, weekly 월 06:30 `collect.weekly`, 매월 1일 05:00 `reference.refresh`, 기동 시 reference 비어 있으면 1회.
2. `runner.py`: `job_run` 폴링(queued → running → done/failed, stats·error_text), DB 락(동시 실행 2개 → 하나만), `main(argv)`(`--once` 지원).
3. `collect.py`: collectors(WP1) 호출 → `normalize.store`(WP2)로 저장 → `change_event`.
4. `detect.py`: 팝업 이미지 해시·목록 diff·새 공고 → change_event(critical) → 변경 complex_ids.
5. `pipeline.py`(rejudge/bootstrap 본체): 스냅샷 생성(building) → P1 screen → P2 extract(normalize가 넘긴 needs_extract) → P3 audit → P4 classify(포함/제외 7클래스, 호재 5클래스) → P5 compare(needs_compare) → P6 noul(3 horizon) → P7 rerank(후보군 전체 1회, §6-5) → 점수(`analysis` — score_inputs를 DB에서 조립: unsold_scope_codes·intake_checked_at·필드 라벨 등 2026-10-09.2 필드 채움) → P8 decide(시나리오 5 + 사용자; 요건 사전 계산 문자열) → P9 verify(claims 원자 분할) → `score_run/score_component/score_total/ladder/decision/claim` 저장 → contradicted 0이면 `snapshot.publish`. 판정 호출은 전부 `judge.get_adapter()` + `judge.pipeline` 단계 함수로만. decide tie는 `analysis.score.decide_outcome`이 원본(judge 쪽 중복은 쓰지 않음).
6. `rejudge.py`: 변경 complex_ids만 재판정; 캐시(input_hash)로 변화 없는 날 실제 호출 0.
7. `notify.py`: WEBHOOK_URL 있으면 critical change_event만 전송(guard 통과), 없으면 no-op.
8. `degraded.py`: JudgeUnavailable → 수집·정규화는 계속, `degraded=true` 플래그(DB 또는 상태 파일 — API가 읽을 수 있게; 계약에 위치가 없으면 요청), 점수 미계산, 복구 감지 시 미처리 rejudge 자동 등록.
9. 판정기 버전/모델 변경 감지 → change_event(judge, version, critical) + 전체 재판정 1회.

## 완료 기준
- [ ] 변경 없는 날 시뮬레이션 → 판정기 실제 호출 0, change_event 0, rejudge 0 (T8)
- [ ] 팝업 이미지 변경 픽스처 → change_event critical 1 + rejudge job 1
- [ ] 동시 실행 2개 → 하나만 동작
- [ ] 판정기 다운(Mock JudgeUnavailable) → 수집 성공 + degraded 플래그 + 점수 미계산 + 복구 시 rejudge 자동 등록 (T18)
- [ ] region.bootstrap 종단 테스트: 녹화 픽스처(collectors 테스트 픽스처 재사용) + MockAdapter(`contracts/fixtures/incheon_gimpo_2026-10-08/judgments`)로 스냅샷 published까지, score_total·ladder·decision 행 생성
- [ ] 재판정 2회 → 두 번째 실제 호출 0 (T17)
- [ ] human_check 후 rejudge → 해당 단지 후보 포함 (T3 후반)

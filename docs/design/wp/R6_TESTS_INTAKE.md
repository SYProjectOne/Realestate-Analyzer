## 4. 실제 판정기 재생 (읽기 전용 + 버리는 SQLite 캐시, tools/call 8)

운영 DB 는 읽기만 했다(스냅샷 1 의 HTTP 200 접수 행 71 → 동일성 대상 70). 새 코드로 항목을 만들어 실제 JEV(`jev-mcp@latest`, 루트 `.env`
자격 증명 — 출력 없음)에 별도 SQLite 캐시로 보냈다. 운영 DB·운영 캐시에는 아무것도 쓰지 않았다. 호출: 동일성 2배치 × 2회(세대수 라벨
수정 전·후) + 접수 1배치 × 4회(문맥+페이지 B, 문맥만 A, 최종 코드 A, 라벨 수정 뒤 동일성 통과 집합) = 8.

설계 선택의 근거(같은 재생): 접수 항목에 **후보 문맥 + 페이지 전체**를 넣으면(B) 힐스테이트 구월아트파크·오션포레·시티오씨엘 8단지·
엘리프 검단 포레듀의 open·auto 4건이 review 로 흐려졌다(가능 4 → 0). **후보가 있으면 문맥만, 없으면 페이지 문구**(A, 채택)는 4건을
유지했다. 세대수 라벨 없이 '공급 세대: 50세대'를 주자 '총 126세대' 페이지(중앙하이츠)가 0.45 review 로 떨어져 라벨을 '청약홈 공급
세대수(단지 총 세대수와 다를 수 있음)'로 바꿨다.

**인천 실행 예상 효과**: 접수 '가능·미정' 6 → 8(민간 판정 범위 후보 +1 — 검암역자이르네; 프라베뉴는 공공·범위 경계), 동일성 미확인 19 → 12,
사유가 '동일성 미확인'에서 '문구로 판단 불가'로 바뀌는 7행(페이지에 접수 문구가 없다는 정직한 사유). 대시보드가 크게 차지 않는 남은 원인은
입력 조립이 아니라 **페이지 내용**(접수 안내가 팝업 그림 안 — 33행)·**수집 실패 25행**·**기준일 없는 일정 문구**(숭의역 노르웨이숲:

1. 팝업 **그림** OCR(공고문 OCR D5 재사용)로 접수 안내 문구를 DOM 텍스트에 붙이기 — 33행이 '문구로 판단 불가'인 주원인. 새 라이브러리 없이 가능한지 WP1a 확인 필요.
2. 접수 classify 에 **기준일**(또는 기준 월)을 넣기 — 일정 문구('정당계약 10.19~21')를 판정기가 지금 기준으로 읽게. 단 항목 텍스트가 날마다 바뀌면 D10-2 분류 복사가 깨진다 — 월 단위·일정 줄이 있을 때만 등 결정 필요(CEO).
3. TLS 실패 9행: robots.txt 를 받을 수 없어(RFC 9309 전부 불허) 본문을 요청하지 않는다. 브라우저(Chromium 검증 — 중간 인증서 AIA 보완)로 robots.txt 까지 받는 경로를 둘지 결정 필요. 인증서 검증 끄기는 제안하지 않는다.
4. **계약 변경 요청(G7 접수 확인 대기열)**: 대상 `contracts/schemas/checklist_item.json` kind enum(또는 새 `GET /ops/intake-queue`) · 내용: '확인 불가' 접수 행을 사유(수집 실패/동일성 미확인/다른 단지/문구로 판단 불가/판정 미해결)별로 묶어 G7 사람 확인 폼(field `intake_status`) 링크와 함께 보이기 · 이유: 지금은 단지 상세 배지로만 보여 운영자가 89행을 한 곳에서 처리할 수 없다 · 영향 WP: WP0(계약), WP2(체크리스트 동기화) 또는 WP5(API), WP6a(G7).

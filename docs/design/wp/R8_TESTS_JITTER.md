# R8-JITTER — G2 표가 로드 직후 입력 없이 계속 떨림 (2026-10-14)

브랜치 `wp/r8-jitter`(main `795ec7f` 기준). 계약·백엔드·`package.json`·차트 코드·차트 기준 이미지는 건드리지 않았다(새 npm 패키지 없음).
표 모양(셀·열·머리줄·배지·`table-layout`)은 그대로다.

## 1. 증상 (사용자 보고)

실데이터 인천 101단지, 데스크톱 창 ~1800×980, `/complexes?scenario=base`, 생활권 = 전체. 페이지가 뜨자마자 표가 "엄청나게 떨리고"
휠을 한 번 굴리기 전까지 멈추지 않는다. 그때 DOM: 행 `style="height: 44px"`(추정값) · 실제 내용 높이 69–135px, 아래 여백 행
`<td colspan="11" style="height: 4758px">`, 머리말 '100 / 101개 나머지 단지를 불러오는 중…', `aria-rowcount=102`.

## 2. 원인 — 실측 ↔ 그린 범위 ↔ 열 너비 되먹임(고정점 없음)

이 표는 **열 너비를 그린 행들의 내용으로 정한다**(auto table layout). R5-FE3 이후 가상 스크롤은 행을 **실측**한다
(`measureElement`, overscan 2, 51행 이상이면 가상화). 그래서 다음 고리가 생긴다:

1. 그린 범위에 행 하나가 들어오거나 빠진다
2. → 그 행 내용 때문에 열 너비가 바뀐다(이름·접수·가격 열 등)
3. → 다른 행들의 줄바꿈이 바뀌어 실측 높이가 바뀐다(ResizeObserver → `resizeItem`)
4. → 바뀐 높이로 다시 계산한 창 범위가 1번의 행을 다시 빼거나 넣는다 → 1번으로

조건에 따라 이 고리에 고정점이 없으면 **입력 없이 매 프레임 두 배치를 오간다**. 실측 자료(probe, 1800×980, 예시 행 101개, 맨 위):

| 프레임 | 그린 행(aria-rowindex) | scrollHeight | 머리줄 열 너비(px) |
| --- | --- | --- | --- |
| 짝수 | 2–13 (12행) | 4896 | 29,**97**,67,192,**147**,166,161,185,**120**,137,199 |
| 홀수 | 2–14 (13행) | 4964 | 29,**82**,67,196,**137**,154,160,185,**157**,135,199 |

가운데쯤에서는 창 위 overscan 행의 높이가 바뀌어 가상 스크롤이 `scrollTop` 을 보정하고(위쪽 행 높이 보정), 끝에서는
`anchorTo: 'end'` 가 전체 높이 변화만큼 `scrollTop` 을 옮겨 **scrollTop 까지 흔들린다**(1678 ↔ 1698, 5717 ↔ 5798). 수정 전에는 이 진동이
프로그램 스크롤(`scrollTop = y`)까지 되돌려 놓는 경우도 있었다(아래 스윕 1800×980 긴 이름: 2400~4400 요청이 전부 2610↔2630 에 묶임).
휠을 굴리면 기준 행이 바뀌어 고정점이 있는 배치로 옮겨 가므로 멈춘 것처럼 보였다.

가설로 본 것 중 원인이 아닌 것: 행 인라인 `height: 44px`(표 행에서는 최소 높이일 뿐, 실측에는 실제 높이가 잡힌다), 브라우저 scroll
anchoring(맨 위 scrollTop 0 에서도 진동 — 앵커링은 0 에서 일하지 않는다), 이어 받기(진동은 '불러오는 중'과 다 받은 뒤 모두에서 같다 —
이어 받기는 행 수만 바꾼다). 머리줄 sticky 는 따로 떼어 시험하지 않았다(높이가 고정이라 위 고리에 끼지 않고, 수정 뒤 진동이 없어졌다).

## 4. 고친 것 (`frontend/src/pages/complexes/ComplexTable.tsx`)

가상 스크롤 `rangeExtractor` 에 **범위 히스테리시스**(`nextHeldRange` · `useHeldRange`)를 넣어 고리 4번을 끊었다:

- 기본 범위는 그대로 창 ± overscan.
- **기준 행과 행 수가 그대로인 동안** 실측 때문에 줄어든 범위는 앞뒤 각각 최대 `RANGE_HOLD`(2)행까지 이전 범위를 유지한다. 넓어지는 건
  바로 따른다. 범위가 줄지 않으니 되먹임이 한 방향으로만 움직여 몇 프레임 안에 고정점에 닿는다(진동하던 두 배치 중 넓은 쪽).
- 기준 행 = 가상 스크롤의 자체 보정이 화면 위치를 지키는 행: 보통은 **창 맨 위 행**(위쪽 행 높이 보정), 마지막 행이 창 안이면
  **마지막 행**(`anchorTo: 'end'` 보정은 맨 위 행을 옮긴다).
- 기준 행이 바뀌면(= 사용자 스크롤) 붙잡은 범위를 버린다 — 스크롤 중 그리는 행 수·T16 프레임 비용은 그대로.

고르지 않은 대안: `table-layout: fixed`·열 너비 고정(`<colgroup>`)은 고리 2번을 끊지만 열 너비(모양)가 바뀐다(R5-FE3 에서도 같은 이유로
되돌림). overscan 키우기·짧은 목록 기준(50) 올리기는 고정점이 없는 배치를 다른 행 수로 옮길 뿐이다. 실측을 끄면 R5-FE3 의 프레임
여유가 사라진다.

단위 테스트 `src/pages/complexes/heldRange.test.ts`(8건): 12↔13 진동 입력이 13행에서 멈춤, 붙잡는 폭 상한, 넓어짐은 바로, 맨 위 행이
바뀌면 버림, 끝에서는 맨 위 행이 바뀌어도 유지, 행 수가 바뀌면 처음부터, 빈 목록.

수정 뒤 `jitter.spec.ts` **4/4 통과** — 모든 경우·단계에서 정착 뒤 변화 0, 서로 다른 상태 1, 스윕 안 멈춘 자리 0, 끝 단계는 끝에 붙어 있음.

## 7. DECISIONS 후보

- D10-8 보강 후보: G2 가상 스크롤은 실측 행 높이 + **범위 히스테리시스**(기준 행 그대로인 동안 줄어든 범위를 앞뒤 2행까지 유지)를 쓴다 —
  auto table layout 에서 실측과 그린 범위가 서로를 바꾸는 진동을 막기 위해. 회귀 테스트 `e2e/pages/jitter.spec.ts`.

## 8. 남은 것 / 하지 않은 것

- 실데이터(인천 101단지) 화면은 직접 띄우지 않았다(사용자 앱 5173/8000 은 손대지 않음). 같은 모양을 MSW 예시 행 101개 + 긴 이름 +
  이어 받기 지연으로 재현했고, 사용자 창 크기 1800×980 에서 수정 전 실패 · 수정 뒤 통과를 확인했다.
